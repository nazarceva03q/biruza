## Локальный запуск

Node.js 22, внешние зависимости для сайта и облачных функций не нужны.
`npm start` – http://127.0.0.1:4177. `npm run check` и `npm run build` проверяют и собирают статическую часть.
`node --test bot/tests/*.cjs` проверяет backend с изолированными заменами Object Storage/VK.
Это не подтверждение доступа/поведения реальных облачных сервисов.

## Каталог и формы

`catalog-data.js` – резервный каталог, `config.js` – только публичные настройки.
Облачный манифест загружается через `catalogEndpoint`; сбой сохраняет резервные карточки и исходные фото.
В каждой галерее оформления новые фото добавляются после существующих. Сертификаты не заменяются.
Существующие карусели, зум, корзина, избранное и квиз сохраняются.

`request-client.js` отправляет JSON с Idempotency-Key; контракт `{accepted:true,id:"BR-…",delivery:"pending"}` означает надёжное сохранение, а не подтверждение доставки VK или заказа.
При неизвестном результате форма и корзина не очищаются; повтор использует прежний ключ.
В sessionStorage хранятся только ключ попытки и SHA-256 отпечаток, без исходных контактов/текста.
Если данные изменены при неизвестном исходе, клиент не отправляет автоматически вторую заявку.

`catalogEndpoint` подключён к проверенной функции Yandex Cloud; бот управления и чтение каталога развёрнуты. `inquiryEndpoint` и `consentVersion` пока пустые: реальный приём заявок НЕ включён.
Форма сообщает об этом вместо имитации успеха. Реквизиты оператора пользователь отложил; они не выдумываются.
Публичный запуск требует сквозных тестов и актуального согласия/политики с действительными реквизитами.

## Облачный backend

`bot/README.md` описывает функции, окружение, права, срок хранения, проверки и настройку.
`python scripts/package-cloud.py` создаёт четыре архива без секретов в игнорируемом `artifacts/cloud/`.
Backend не использует REG/PHP и не связан с ресурсами другого магазина.

## Публикация

Workflow подготовлен для GitHub Pages, публикует ТОЛЬКО `dist/`, а не корень репозитория.
Pages публикуется через GitHub Actions. Временный адрес: https://nazarceva03q.github.io/biruza/. Переключение домена biruza33.ru требует отдельной настройки DNS и проверки.
Исторические записи HOSTING.md о REG не описывают новую схему backend.
`bot/`, служебные сценарии, интервью, handoff и локальные материалы не входят в публичную сборку.
Секреты задаются в окружении облака, никогда в config.js/репозитории/чате.
