# Бирюза

Сайт цветочного магазина. Владимир, ул. Мира, 53. Ежедневно 9:00–20:00. Телефон: +7 (910) 178-39-64.

## Запуск

Node.js 18+; внешние зависимости для сайта не нужны.

```sh
npm start
```

Открыть http://127.0.0.1:4177. `npm run check` проверяет файлы и синтаксис; `npm run build` собирает только публичные файлы в `dist/`.

## Что готово

Адаптивная главная по technical-specification.md, фирменная палитра, локальные шрифты, восстановленный логотип на прозрачном фоне, категории цветов и шаров, контекстные обращения, подготовка и копирование текста, телефон, карта с поиском адреса, FAQ, fade-up разделов, подъём карточек, плавные якоря и параллакс декоративных окружностей. Reduced motion отключает движение.

По последнему запросу фотографий нет, вместо них подписанные области. Отзывы обозначены как будущий контент. Карточки являются направлениями подбора, а не конкретными товарами и остатками. На сайте используется среднее тире «–».

## Данные и подключения

`config.js` – контакты и ссылки. Заполнить `vkUrl`, `maxUrl`, `telegramUrl`: иконки автоматически станут рабочими ссылками. Пока они честно сообщают, что ссылка появится позже.

`data.js` – направления каталога и FAQ. Фотографии и проверенные цены реальных товаров нужно добавить после получения от магазина.

По умолчанию форма только готовит текст, не отправляет его. Уже работает прямой телефон. Для настоящей отправки нужен серверный обработчик и согласованные документы. Заполнить `inquiryEndpoint`, `privacyUrl`, `consentVersion` только после реальной проверки. Обработчик должен возвращать `{ "accepted": true, "id": "реальный-id" }` после надёжного приёма. Клиент обрабатывает ошибку/таймаут и передаёт requestId для защиты от дублей. Серверная реализация и секреты в этот статический проект не включены.

Актуальность стартовой цены букетов 1 500 ₽, доставки 350 ₽ и бесплатности свыше 10 000 ₽ необходимо подтвердить до запуска приёма заказов. Свадебный декор, сертификаты, подписки, мастер-классы и гарантии не добавлены.

## Публикация

Размещать содержимое `dist/` на статическом хостинге. Репозиторий и GitHub Pages – разные действия; публикация на домене не входит в сохранение исходника. Не публиковать интервью, ZIP-референсы, reference-analysis/ и служебные материалы. Эти файлы исключены из Git либо из публичной сборки.

`research.md`, `structure.md` и `technical-specification.md` сохраняют исследование и исходные решения; последние пользовательские уточнения и фактическая реализация описаны в DESIGN.md и этом README.

## Проверка в браузере

Проверены ширины 320, 375, 390, 768, 1024 и 1440 px, независимые фильтры, бюджет, подготовка текста, меню, reduced motion и отсутствие ошибок браузера. Отдельно проверен будущий клиент отправки с перехваченными тестовыми ответами 503/200: ошибка не показывает успех и не стирает ввод; повтор сохраняет requestId. Реальные обращения при проверке не отправлялись.

Для повторения: `node scripts/browser-check.cjs` и `node scripts/request-check.cjs` при работающем `npm start`. Нужен Playwright в среде разработки; он не требуется посетителям или сборке сайта. Браузер можно указать через `BROWSER_PATH`, модуль для теста отправки – через `PLAYWRIGHT_PATH`. Отчёт и снимки сохраняются локально в игнорируемую папку `artifacts/`.
